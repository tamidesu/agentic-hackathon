# Halyk AI Challenge — проверка ковенантов по «грязным» документам

Агент читает разнородные финансовые документы и определяет, нарушены ли
финансовые ковенанты корпоративных кредитов: `status`, фактическое значение
показателя `actual` и транзакция-доказательство `evidence_txn_id`.

---

## Главное решение: модель извлекает, код считает

**Обучения нет.** Двенадцать сценариев — это тест, а не обучающая выборка.
Задача не «выучить закономерность по примерам», а «прочитать документ и
посчитать по написанному в нём правилу», причём правило у каждого заёмщика
своё и лежит в тексте договора.

| | роль |
|---|---|
| **LLM** | читает документ и заполняет структуру: порог, направление, период, список связанных сторон, категория операции. Ни одного числа не выдаёт как ответ |
| **Код** | берёт заполненные структуры и вычисляет детерминированно, с полной трассировкой |

**RAG не нужен.** Ретрив решает проблему «непонятно, какой документ читать».
Здесь понятно детерминированно: `account_id` из текста → `scenario_id` через
реестр транзакций, 190 документов из 200 привязываются однозначно. На один
расчёт нужны 3–4 документа, около 22k токенов. Векторная база здесь добавила
бы только шанс не подтянуть нужный кусок.

## Архитектура

```
documents/*.pdf ──pdfplumber / зрение──► artifacts/01_texts/
                                              │
                        детерминированный роутер: тип + заёмщик
                                              │
              ┌───────────────────────────────┴───────────────────┐
              │      на каждого заёмщика, ветки независимы         │
              │  LLM: договор → спецификации ковенантов           │
              │  LLM: аудит   → корректировки                     │
              │  LLM: KYC     → связанные стороны                 │
              │  LLM: реестр  → категории операций                │
              │                     ↓                             │
              │  КОД: агрегаты → status / actual / evidence        │
              └───────────────────────────────────────────────────┘
                                    ↓
                            submission.json
```

Каждый шаг — отдельный модуль с **явным контрактом**: читает файлы-артефакты,
пишет файлы-артефакты. Любой шаг можно перезапустить или заменить, не трогая
соседние.

```
artifacts/
  01_texts/{doc_id}.txt        извлечённый текст          (шаг 2)
  02_doc_index.json            тип + заёмщик + редакция   (шаги 3, 4)
  03_covenants.json            спецификации ковенантов    (шаг 5)
  04_adjustments.json          аудиторские корректировки  (шаг 7)
  05_related_parties.json      связанные стороны          (шаг 8)
  06_ledger_clean.csv          очищенный реестр           (шаг 9)
  07_ledger_categorized.csv    + категории                (шаг 10)
  08_ledger_final.csv          + корректировки            (шаг 11)
  09_results.json              status / actual / evidence (шаги 12, 13)
  submission.json                                         (шаг 14)
```

## Ключевые решения и почему именно так

### Ковенант — дерево выражений, а не тип из списка

Разбор всех 36 ковенантов публичного набора дал шесть форм: агрегат против
порога, отношение агрегатов, максимум из статей, агрегат минус максимум,
условный (springing) тест, агрегат с внебалансовой суммой.

Фиксированный список типов был бы ловушкой: приватный набор принесёт седьмую
форму, и дописывать код пришлось бы в боевом окне. Поэтому введён один
примитив — агрегат по категории — и операции над ним:

```python
B1/6.1   DIV(SUB(AGG(revenue), AGG(opex)), AGG(interest))   # покрытие процентов
P10/6.2  SUB(AGG(revenue), MAX(AGG(payroll), AGG(taxes)))    # минус наибольшая статья
P8/6.1   ADD(AGG(payroll), DISCLOSED(severance))             # с внебалансовым
```

Новая форма — новая комбинация существующих узлов, без правки кода.
Незнакомый узел помечает ячейку флагом, а не роняет прогон.

### Ничего из публичного набора не зашито в код

Приватный датасет назовёт файлы, счета и сценарии иначе, поэтому всё
выводится в рантайме:

| что | как определяется |
|---|---|
| реестр транзакций | CSV с колонками `txn_id / account_id / amount` |
| шаблон ответа | JSON со структурой ячеек |
| каталог документов | по концентрации файлов-документов |
| `account_id → scenario_id` | из реестра: `txn_id` начинается со `scenario_id` |
| шумовые счета | их сценария нет в шаблоне (а не «префикс 9xxx») |
| названия компаний | выучиваются из привязанных документов по различительности |
| отчётный период | диапазон дат реестра, без округления до года |
| курс валюты | из раскрытой аудитором пары «сумма в валюте → платёж в долларах» |

### Действующий договор выбирается по периоду, а не по пометке

Период действия написан в самом договоре; пометка «НЕДЕЙСТВУЮЩАЯ РЕДАКЦИЯ»
критерием не является. Шаг 3 не решает актуальность вообще — все договоры
выходят одним типом, а шаг 4 выбирает тот, чей период соответствует
отчётному. Расхождение между периодом и пометкой сообщается отдельно.

### Доказательство: контрфактуальной проверки недостаточно

Условие запрещает считать доказательством строку, которая «лишь вносит вклад
в сумму». Простой перебор «убери — изменился ли вердикт» выдаёт именно её:
в агрегате из десяти платежей удаление любого крупного переворачивает
результат.

Поэтому условия два. Кандидаты берутся только среди операций, **чья трактовка
продиктована документом** — переклассификация аудитором, восстановленная из
документа сумма, правило отсечения, признание контрагента связанной стороной
по KYC. И уже среди них ищется решающая.

### Тихая деградация недопустима

Каждое место, где данные могут не сойтись, кричит:

* пустой агрегат → «вероятно расхождение словаря категорий»;
* ноль связанных сторон → «вероятно провал разметки, а не отсутствие платежей»;
* распознанный документ с чужой письменностью → сравнение с медианой корпуса;
* `tesseract` без языковых пакетов → отказ вместо правдоподобного мусора;
* сумма без указания направления → флаг вместо молчаливого допущения знака.

## Что найдено в данных

| находка | почему важно |
|---|---|
| Пометка `ИСПОЛНИТЕЛЬНЫЙ ЭКЗЕМПЛЯР` стоит на **обеих** редакциях договора | признаком актуальности не является |
| Фраза «Знай своего клиента» встречается в 18 документах, а KYC-досье 12 | остальные — договоры, ссылающиеся на KYC в пункте 6.3 |
| Пункт 6.1 у P1 — капиталоёмкость, у P6 — доля связанных сторон | хардкод по номеру пункта обнуляет ячейки |
| Две операции в реестре **без суммы** | восстанавливаются из документов, одна — из единственной казначейской записки |
| Счёт на 72 146.75 EUR в аудите отсутствует в реестре | его назначение — раскрыть курс: 1.16 USD/EUR |
| Отчётность Sarybel Energy Holding не содержит ни счёта, ни имени заёмщика | это материнская компания P5, нужна для ковенанта по Группе |
| B1/6.2: «их сумма не является показателем» | нужен максимум из статей, а не сумма |

## Запуск

```bash
pip install -r solution/requirements.txt
# для распознавания сканов через tesseract (не обязательно при наличии ключа):
#   apt-get install poppler-utils tesseract-ocr tesseract-ocr-rus

export ANTHROPIC_API_KEY=...        # нужен шагам 5, 7, 8, 10
export LLM_MODEL=claude-opus-5      # необязательно

python -m pytest solution/tests -q                 # весь набор
python -m pytest solution/tests -q -m "not slow"   # быстрый прогон, ~10 с
```

Датасет в репозитории не хранится. Положите его так:

```
agentic-hackathon/
  agentic-bank-public/     # documents/, реестр, submission_template.json
  solution/
```

Проверка собранного ответа **без ключа ответов** — этот же инструмент
работает на приватном датасете:

```bash
python -m solution.pipeline.validate \
  --submission runs/latest/submission.json \
  --template agentic-bank-public/submission_template.json \
  --ledger agentic-bank-public/master_ledger_2025.csv
```

## Тесты

Проверяется не «код запускается», а заявленные гарантии. Несколько примеров:

* повторный прогон не делает ни одного сетевого вызова и даёт тот же результат;
* цитата, отсутствующая в документе, отклоняется — защита от выдуманных чисел;
* отменённая редакция не может пройти как действующая;
* привязка выживает при переименовании всех счетов и сценариев;
* `status` не в том регистре обнуляет ячейку — валидатор ловит до отправки;
* при пустом расчёте всё равно собирается валидный `submission.json`.

Медленные тесты (полное извлечение корпуса, ~80 с) помечены `slow`
и отключаются флагом `-m "not slow"`.
